# 틈새(niche) 기반 모델 진화 — 설계 스펙

작성일: 2026-10-10 · 상태: 초안(사용자 검토 대기) · 패키지: `lerp/niche/` · CLI: `lerp niche ...`

## 1. 목표와 비목표

**목표.** 학습 없이 가중치만 섞는 탐색이 아니라, 병합 + 짧은 학습 + 다양성 유지를 한 루프로 묶어 *새 스킬을 배우고, 합쳐지고, 다음 세대의 부모가 되는* LoRA 어댑터 집단을 만든다. 저사양 기기에서 돌아가야 한다.

**하드웨어 기준.** 하한선은 CPU 전용·RAM 8GB 이하, 검증 기기는 Intel Arc 140V(16GB). "이 기기에서 돈다"만으로는 부족하며, CPU-8GB 프로필의 완주를 따로 실측한다.

**비목표(YAGNI).** 다른 모델 가족 간 병합, 분산 실행, 웹 UI, 하이퍼파라미터 자동 튜닝, 기존 `lerp evolve`의 수정.

## 2. 배경: 왜 이 설계인가

기존 `lerp evolve`(`lerp/evolution/`, `experiments/RESULTS.md`)는 한 계통을 키우는 구조다. 같은 학습 스텝의 단일 어댑터 대조군을 이기지 못했다. 다만 비교가 조건 일치(데이터 구성, rank, 시작점)가 아니었으므로 "진화가 불가능하다"는 결론은 아니고, "이득이 입증되지 않았다"가 사실이다. 원인으로 의심되는 것(확정 아님): 자식 여러 명에게 컴퓨트를 쪼개 각 계통이 덜 배움, 학습 재시작, 다양성 유지 장치 없음. 이 설계는 세 번째를 직접 다루고, 앞의 둘은 연속 학습과 단계 평가로 줄인다.

## 3. 구성 요소

경계가 분명한 단위들이다. 기존 코드는 import로 재사용하고 수정하지 않는다.

| 단위 | 책임 | 재사용 |
|---|---|---|
| `Organism` | 어댑터 경로, 계보, 연산자 기록, 스킬 프로필(가족별 점수), 문항별 정오 | `evolution.archive.Organism` 확장 |
| `NicheArchive` | 프로필을 격자 칸으로 나눠 칸당 엘리트 최대 k=2개를 보관, 삽입·교체 규칙, 밀려난 어댑터 삭제 | `evolution.archive` |
| `Selector` | 부모 쌍 선택. 문항 단위로 정답이 엇갈리는 비율(보완성)에 비례, 오래 안 뽑힌 칸에 가산점 | — |
| `Operators` | 병합(`graft`/`blend`), 짧은 학습, SVD 압축 | `evolution.combine`, `evolution.learning` |
| `StagedEvaluator` | 1차(작은 문항)로 거르고 2차(큰 문항)로 확정, 쌍체 McNemar | `statistics.mcnemar`, `problems.verify` |
| `BudgetManager` | 세대별 메모리·스텝·평가 문항 상한, 하드웨어 프로필, 개체 단위 체크포인트와 재개 | — |

격자 축: 스킬 점수를 3구간(낮음/중간/높음, 경계 1/3·2/3)으로 나눈다. 축은 founder 집단의 dev 점수 분산이 큰 상위 3개 스킬로, 0세대 평가 직후 한 번 정하고 이후 바꾸지 않는다(최대 27칸).

## 4. 한 세대의 흐름

1. Selector가 칸과 부모 쌍을 고른다.
2. 병합한다(연산자를 개체 메타데이터에 기록).
3. 자식이 부모 프로필에서 가장 약한 스킬을 우선해 짧게 학습한다. 연속 학습(옵티마이저 상태 이어받기, 전역 스케줄)이 기본이며, 다른 세션의 restart factorial 결과로 확정한다.
4. rank 16으로 SVD 압축하고 보존 에너지를 기록한다.
5. 1차 평가: 스킬당 40문항. 보관소 평균 근처 이하는 탈락.
6. 2차 평가: 통과분만 스킬당 200문항. 1차와 2차 문항은 겹치지 않으며 assert로 막는다.
7. 보관소 갱신: 자기 칸의 엘리트를 2차 점수 쌍체 비교로 유의하게 이기거나 빈 칸이면 삽입한다.
8. 상태 JSON, 점수, 계보를 저장한다. 보관소의 엘리트가 다음 세대의 부모다.

## 5. 평가 과제

- **1단계(합성 스킬 5~6개).** 산술 `add`/`mul`/`chain`에 문자열 변환 2~3개(뒤집기, 정렬, 개수 세기). 정답이 정확히 검증되고 train/dev/test가 서로 겹치지 않는다(assert).
- **2단계(실제 벤치마크).** ARC/BoolQ/PIQA 계열 LoRA를 founder로 사용. 1단계 기준이 성립한 뒤에만 진행한다.

## 6. 하드웨어 프로필

| | `cpu-8gb`(하한) | `arc`(검증) |
|---|---|---|
| 베이스 | Qwen2.5-0.5B | 0.5B~1.5B |
| 학습 rank | 8~16 | 16 |
| 세대당 후보 수 | 3~4 | 6~8 |
| 짧은 학습 | 30~50 스텝, batch 1~2, 그래디언트 누적 | 100 스텝 |
| 메모리 | 프로세스 RSS 6GB 이하 감시 | 기기 기준 |

- 베이스는 프로세스에 하나만 올리고 어댑터는 필요 시 읽고 쓴다.
- 개체 하나가 끝날 때마다 저장하며, 중단되면 마지막 개체부터 재개한다.
- CPU-8GB 검증은 실제 8GB 기기 대신 프로세스 메모리 상한(Windows Job Object)을 건 CPU 전용 실측으로 대체한다. 이 방법은 8GB 기기와 완전히 같지 않다(OS·캐시·다른 프로세스 영향). 문서에 한계로 명시한다.

## 7. 오류 처리

- 학습·병합·압축 예외는 그 후보만 `failed`로 기록하고 세대를 계속한다. 실패율이 50%를 넘으면 중단하고 원인을 보고한다.
- 입력 어댑터와 산출물의 SHA-256을 기록한다(기존 integrity 방식).
- 비유한(NaN/inf) 가중치는 보관소 진입 전에 거부한다.
- 분리 위반(학습·dev·test, 1차·2차 겹침)은 assert로 즉시 실패시킨다.

## 8. 테스트

코드보다 먼저 작성한다(TDD).

- **단위**: 보관소 삽입·교체·삭제 규칙, 보완성 계산, 선택기 편향 방지, 단계 평가 탈락 규칙, 예산 초과 동작.
- **통합**: 작은 가짜 모델로 한 세대를 CPU에서 수 초 안에 끝까지. 강제 중단 후 재개한 결과가 중단 없는 실행과 같은지.
- **실측**(별도, 짧게): 9절 성공 기준.

## 9. 성공 기준 (실행 전에 코드의 상수로 고정, 사후 변경 금지)

비교 대상은 같은 총 학습 스텝, 같은 데이터 구성, 같은 시작 어댑터와 rank를 쓰는 단일 어댑터 대조군이다. test 문항은 루프가 전혀 보지 않은 것이다.

1. **필수.** 보관소 최고 개체가 대조군보다 *스킬 평균*에서 높고 쌍체 McNemar p<0.05. 스킬 하나만 높은 경우는 인정하지 않는다.
2. **필수.** `cpu-8gb` 프로필로 메모리 상한 안에서 한 세대 이상 완주한다.
3. **참고.** 채운 칸 수(다양성), 새 스킬 습득량, 기존 스킬 유지(손실 0.05 이내).

시드는 최소 3개, 시드별 결과와 신뢰구간을 모두 보고한다. 기준 1을 못 넘으면 "못 이겼다"고 그대로 기록한다.

## 10. 다른 세션과의 조율

- 이 작업은 `lerp/niche/`, `tests/test_niche_*.py`, 이 스펙 문서에 한정한다. 다른 세션이 진행 중인 `lerp/evolution/*`, `experiments/restart_*`, `experiments/RESULTS.md`는 수정하지 않는다.
- `Lerp` 저장소의 작업 트리를 두 세션이 공유한다. 커밋은 사용자 허락 후 자기 파일만 선택해서 한다.
- Arc GPU는 하나다. 실험 전에 상대 세션에 알리고, 상대의 12모델 평가가 끝난 뒤에 돌린다.
- 미해결 입력: restart factorial 결과(연속 vs 분할 학습). 4절 3단계의 기본값을 이 결과로 확정한다. 결과가 없으면 연속 학습으로 진행한다.

## 11. 알려진 위험

- 짧은 학습으로는 0.5B 모델이 새 스킬을 거의 못 배울 수 있다(기존 `chain` 정확도 10% 내외). 이 경우 틈새 신호가 노이즈에 묻힌다. 합성 스킬 난이도를 낮춘 쉬운 변형을 준비한다.
- 소표본 평가로 엘리트를 고르면 우연한 승자를 올릴 수 있다(winner's curse). 2차 평가와 쌍체 검정, 최종 test 분리로 완화하지만 완전히 제거되지는 않는다.
- 격자 축 선택(3절)이 결과에 영향을 줄 수 있다. 규칙은 고정했지만 다른 선택과의 민감도는 검증하지 않는다.
